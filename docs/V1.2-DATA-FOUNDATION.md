# Kayda Intelligence — V1.2 Data Foundation

## Purpose
V1.2 separates the domain model from the interface and introduces browser-local persistence so records survive page reloads without requiring a paid service. The hydration/write sequence is guarded so the initial demo state cannot overwrite an existing saved workspace.

## Current persisted objects
- Businesses
- Contacts
- Deals
- Projects
- Tasks
- Priorities
- Activities

## Why local persistence first
This lets the operator test workflows without creating a cloud account or paying for infrastructure. The PostgreSQL/Prisma schema in `prisma/schema.prisma` is the migration contract for the next persistence layer.

## Next migration
1. Create Supabase/PostgreSQL project.
2. Add DATABASE_URL and server-only database client.

## Non-negotiable architecture
UI components must not own database logic. Domain operations live behind repository/service functions. AI agents will call controlled tools against those services rather than writing arbitrary database queries.
